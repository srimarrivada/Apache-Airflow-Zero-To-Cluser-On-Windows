# Airflow REST API

Apache Airflow exposes a REST API which is available through the Airflow web server. This API enables seamless integration with Airflow, allowing to automate various tasks based on their frequency and requirements. For example, a DAG can be triggered externally without accessing Airflow UI or CLI by making a simple HTTP request in Python or CURL. The Airflow API is helpful to perform tasks like getting information about tasks and DAGs, getting Airflow configuration, updating DAGs, listing users, adding and deleting connections, etc.

The Airflow REST API provides a number of REST API endpoints across its objects, which can be found in the [Airflow REST API Reference](https://airflow.apache.org/docs/apache-airflow/stable/stable-rest-api-ref.html). Most of these endpoints accept input in JSON format and return output in JSON format.

A URL for Airflow API requests has the following format:

| Version | URL |
|---|---|
| Airflow 2.x | `http://<webserver-host>:<port>/api/v1/<endpoint>` |
| Airflow 3.x | `http://<apiserver-host>:<port>/api/v2/<endpoint>` |

While making any Airflow API request, the following header should be added:
```
Content-Type: application/json
```

On Windows, the Airflow API can be accessed through Python IDEs like **Jupyter Notebook**, **VS Code** or even **Python CLI** using the `requests` library.

> Before running any REST API command from Airflow installed in WSL, activate the Python virtual environment:
> ```bash
> source airflow-env/bin/activate
> ```
> 
> If you don’t have Python installed already in Windows, you can install it from [Python Downloads](https://www.python.org/downloads/) website and set `Python` install path and `Python\Scripts` path in `PATH` environment variable.
>
> Open **Command Prompt** or **Windows PowerShell** and install Python `requests` library and open Python CLI:
> ```powershell
> pip install requests
> python
> ```

## 1.1 Generate Token
To interact with Airflow API, one must pass the JWT (JSON Web Token) in the header of the request. The JWT can be generated by making a `POST` request to the `/auth/token` endpoint passing the username and password of the Airflow UI.

In **Ubuntu** terminal, run the following commands to get JWT for Airflow 3 version API running locally at [http://localhost:8080](http://localhost:8080).  
Replace `<admin-password>` with the value available in `simple_auth_manager_passwords.json.generated` file in `$AIRFLOW_HOME` directory.

```bash
ENDPOINT_URL="http://localhost:8080"
curl -X POST ${ENDPOINT_URL}/auth/token \
  -H "Content-Type: application/json" \
  -d '{
     "username": "admin",
     "password": "<admin-password>"
  }'
```

## 1.2 List DAGs
To fetch the list of all DAGs, make a `GET` request to `/dags` endpoint _(replace `<token>` with the JWT generated above)_:

```bash
curl --verbose 'http://localhost:8080/api/v2/dags' -H 'content-type: application/json' -H 'Authorization: Bearer <token>'
```

**To access it from Python:**
```python
import requests
import json

airflow_url = 'http://localhost:8080'
end_point = '/api/v2/dags'
url=f'{airflow_url}{end_point}'

token='<token>'
headers = {'content-type': 'application/json',
           'Authorization': f'Bearer {token}'
           }

response = requests.get(url=url, headers=headers)
print(json.dumps(response.json(), indent=2))
```

## 1.3 Get DAG Details
To retrieve information about a specific DAG, send a `GET` request with the DAG ID to `/dags/{dag_id}/details` endpoint.  
For example, to get details for `example_bash_operator` _(replace `<token>` with the JWT generated above)_:
```bash
curl -v -X GET http://localhost:8080/api/v2/dags/example_bash_operator/details -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>'
```

**To access it from Python:**
```python
import requests
import json

```

## 1.5 Unpause DAG
To unpause a specific DAG, send a PATCH request with the DAG ID to `/dags/{dag_id}` endpoint and pass a payload.  
For example, to unpause `example_python_operator` _(replace `<token>` with the JWT generated above)_:
```bash
curl -X PATCH http://localhost:8080/api/v2/dags/example_python_operator -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' -d '{"is_paused": false}'
```

In the output, `is_paused` is set to `false`, which indicates the DAG is unpaused. You can confirm this in the Airflow UI under the **Dags** tab.

**To unpause `example_bash_operator` from Python:**
```python
import requests
import json

airflow_url = 'http://localhost:8080'
end_point = '/api/v2/dags/example_bash_operator'
url=f'{airflow_url}{end_point}'

token='<token>'
headers = {'content-type': 'application/json',
           'Authorization': f'Bearer {token}'
           }
data = {'is_paused': False}

response = requests.patch(url=url, headers=headers, data=json.dumps(data))
print(json.dumps(response.json(), indent=2))
```

## 1.6 Trigger DAG Run
To trigger a specific DAG, send a `POST` request with the DAG ID to `/dags/{dag_id}/dagRuns` endpoint and pass `logical_date` in `YYYY-MM-DDTHH:MM:SSZ` format.  For example, to trigger `example_python_operator` _(replace `<token>` with the JWT generated above)_:
```bash
curl -X POST http://localhost:8080/api/v2/dags/example_python_operator/dagRuns -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' -d '{"logical_date":"2026-03-15T01:05:00Z"}'
```

Go to Airflow UI and open `example_python_operator` DAG, where you should see the DAG got triggered and completed successfully.

**To trigger `example_bash_operator` from Python:**
```python
import requests
import json

airflow_url = 'http://localhost:8080'
end_point = '/api/v2/dags/example_bash_operator/dagRuns'
url=f'{airflow_url}{end_point}'

token='<token>'
headers = {'content-type': 'application/json',
           'Authorization': f'Bearer {token}'
           }
data = {'logical_date': '2026-03-16T05:56:00Z'}
response = requests.post(url=url, headers=headers, data=json.dumps(data))
print(json.dumps(response.json(), indent=2))
```

## 1.8 Delete DAG Run
To delete a specific DAG run, send a `DELETE` request to `/dags/{dag_id}/dagRuns/{dag_run_id}` endpoint.  
Use your own DagRun ID as returned by the `dagRuns` endpoint _(replace `<token>` with the JWT generated above)_:
```bash
curl -X DELETE http://localhost:8080/api/v2/dags/example_python_operator/dagRuns/manual__2026-03-11T14:31:57.775446+00:00 -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>'
```

Verify the DagRun has been deleted using Airflow CLI:
```bash
airflow dags list-runs example_python_operator
```

It returns a `No data found` message since there are no more runs.

**To delete from Python:** _(replace `<dagRunID>` with yours)_
```python
import requests
import json

airflow_url = 'http://localhost:8080'
end_point = '/api/v2/dags/example_bash_operator/dagRuns/`<dagRunID>'
url=f'{airflow_url}{end_point}'

token='<token>'
headers = {'content-type': 'application/json',
           'Authorization': f'Bearer {token}'
           }

response = requests.delete(url=url, headers=headers)
print(response.json())
```
